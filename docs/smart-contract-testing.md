# Автоматическое тестирование смарт-контрактов

## Среда и команды

Тесты запускаются в уже согласованном стеке Hardhat 3: Node.js 26.13.0,
Hardhat 3.21.2, Viem toolbox и встроенный Node.js test runner. Использована
изолированная in-memory Hardhat Network: каждый сценарий получает snapshot
через `loadFixture`, поэтому тесты не зависят от порядка исполнения.

Выполненные команды:

```powershell
npm run compile
npx tsc --noEmit
npm test
npx hardhat test --coverage
```

Для времени применяются `networkHelpers.time.increaseTo` и
`networkHelpers.time.increase`; реальных ожиданий на 30 или 365 дней нет.

## Обнаруженные проблемы и исправления

Дефектов в реализации `AccessToken.sol` и `AIServiceAccess.sol` тесты не
выявили, поэтому контракты на этапе тестирования не изменялись.

При разработке набора тестов исправлены сами тестовые данные:

- сценарий MONTHLY→YEARLY первоначально выдавал тестовому пользователю 1000
  STK, хотя на две покупки нужно 1100 STK; сумма пополнения и approve
  исправлены на 1100 STK;
- результаты ABI getter-методов приведены к `bigint` там, где TypeScript не
  смог вывести тип из артефакта, что устранило ошибки `TS18046`.
